StreamGate

Plataforma Definitiva de Ingestão e Segurança de Ativos em Larga Escala

📖 Descrição

O StreamGate é uma plataforma robusta projetada para ingestão massiva, segurança em tempo real, e análise de dados em ambientes operacionais distribuídos.

Com foco na resiliência e entrega segura (Zero-Trust), ele atua como o principal portão de entrada para uploads institucionais, garantindo que todo arquivo passe por varreduras avançadas de malware e fluxos granulares de conformidade antes de tocar na rede interna.

Visão e Problema

Visão do Produto

Transformar o tráfego de arquivos e uploads em uma experiência 100% visível, rastreável e invulnerável, protegendo infraestruturas corporativas contra malwares distribuídos e vazamento de dados.

O Problema

Superfície de Ataque Exposta

Na era digital, aceitar arquivos do mundo exterior (clientes, fornecedores, anônimos) é o maior risco para redes privadas.

Canais de Ingestão Descentralizados

Empresas recebem arquivos via email, drive, FTP e links avulsos. Não há padronização, nem análise de segurança unificada.

Falta de Telemetria e Auditoria

Operadores não têm visibilidade do volume de ameaças retidas em tempo real ou da volumetria que transita pelos serviços de cloud.

A Solução: A Porta Definitiva

O StreamGate resolve isso criando um fosso (quarentena) isolado entre o mundo exterior e a rede interna da corporação.

Ambiente Isolado (Quarentena)

Uploads suspeitos ficam retidos. Zero chance de infecção para a rede da corporação graças ao pipeline de ClamAV atômico.

Ingestão Multi-Canal

Via Web UI (drag-and-drop), links públicos, webhooks anônimos ou conectores nativos diretos para Google Drive e S3 Bucket.

Analytics em Tempo Real

Telemetria imediata sobre ameaças mitigadas e volumes ingeridos, apoiada por bancos analíticos (ClickHouse) de altíssima performance.

Segurança por RBAC

Controles granulares de quarentena. Somente administradores autorizados com chaves Idempotentes podem forçar liberações.

Engenharia e Arquitetura

Visão Geral dos Componentes

Construído sob uma arquitetura de microsserviços orientada a eventos, visando separação de responsabilidades total.

Command Center (apps/web)

Aplicação frontend imersiva utilizando React, Vite, Tailwind CSS e TypeScript. Estruturada em Feature-Sliced Design. Focada em painéis analíticos ricos e interface administrativa veloz.

API Server (apps/api)

O cérebro transacional. API Restful estrita escrita em Ruby on Rails. Controla Autenticação, mutações de recursos e valida Idempotência das chamadas para garantir consistência perfeita.

Data Worker (apps/worker)

Processador em background escalável (Ruby puro). Escuta as filas de eventos no RabbitMQ, coordena varreduras antivírus (ClamAV) de forma assíncrona e grava logs no ClickHouse.

Contracts (packages/contracts)

A fonte primária de verdade (OpenAPI v3) estabelecida pelo Design-First Approach. Sem ele, a Web e a API não conversam.

Domínios (Bounded Contexts)

Tanto o Frontend quanto o Backend seguem os preceitos de Domain-Driven Design para isolamento de funcionalidades:

  • Auth: Autenticação, registro, tokens, SSO e MFA.
  • Uploads: Gestão de arquivos, links públicos e storage.
  • Analytics: Dashboards, exportações, métricas e auditoria ClickHouse.
  • Operations: Quarentena, DLQ (Dead Letter Queue), Webhooks, RBAC.

Deploy e Inicialização Local

O projeto é inteiramente baseado em contêineres Docker. Possui scripts avançados tanto para Windows (PowerShell) quanto Mac/Linux (Bash).

# Exemplo de subida completa (Cluster Postgres, Redis, Clickhouse, RabbitMQ + Apps)
powershell -ExecutionPolicy Bypass -File .\scripts\dev\dev-up.ps1 -Mode full

Para pipelines de CI e testes locais:

# Run all compliance, E2E, UX Audit and Security Scanners
python .agents/scripts/checklist.py .
